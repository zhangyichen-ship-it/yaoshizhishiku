# 客户知识库边界与数据库说明

## 定位

本项目是部署在客户服务器上的客户知识库。一套部署对应一个公司，因此本项目不实现 SaaS 多租户，也不在知识库业务表中增加 `tenant_id`。云面板是内部总控台，客户不登录云面板。

## 三个项目的责任

| 项目 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 桌面端 | 用户使用桌面 AI、模型和工具 | 不直接管理客户知识库 ACL |
| 云面板 | 公司、员工账号、密码哈希、员工状态、桌面端/知识库/模型产品权限 | 不保存客户知识库文档和向量 |
| 客户知识库 | 文档、分块、向量、知识库、本地 ACL、知识库内员工管理界面 | 不保存员工密码，不维护云端账号事实 |

## 数据库表

### `kb_member`

云端员工在客户知识库中的最小映射。`cloud_user_id` 是跨数据库的外部 ID，不建立跨库外键。

保存：

- 云端用户 ID、用户名、姓名、邮箱；
- 云端账号状态；
- 云端返回的知识库产品生效权限；
- 本地角色和最近同步时间。

不保存：

- 员工密码或密码哈希；
- 云面板服务凭证；
- 云面板完整组织目录。

### `kb_knowledge_base_acl`

本地员工到本地知识库的授权关系：

- `member_id` → `kb_member.id`；
- `knowledge_base_id` → `ai_knowledge_base.id`；
- `granted_by_id` → 本地操作管理员 `sys_user.id`；
- 使用软删除实现撤销和审计，唯一约束防止重复授权。

## 权限判定

普通员工访问指定知识库时必须同时满足：

1. 本地存在未删除的 `kb_member` 映射；
2. 云端账号状态为启用；
3. 云端知识库产品权限为启用；
4. 本地知识库未删除且已启用；
5. `kb_knowledge_base_acl` 存在未删除授权。

任意条件不满足即拒绝。超级管理员可管理本地知识库；无知识库 ID 的普通对话不触发知识库 ACL。

## 云端接口

客户知识库只通过服务端环境变量配置的实例级服务凭证调用：

- `GET /platform/client/kb-instances/{instance_id}/members`：同步员工映射；
- `POST /platform/client/kb-instances/{instance_id}/members`：创建员工；
- `PATCH /platform/client/kb-instances/{instance_id}/members/{user_id}`：更新员工及产品权限；
- `GET /platform/client/kb-instances/{instance_id}/embedding-config`：读取向量来源、模型和地址，不返回 Provider Key。

客户知识库管理员可在“模型配置”页面显式执行“从云面板同步向量模型”。同步只保存非敏感的向量配置，远程 embedding 的 API Key 仍由客户服务器环境变量提供；模型变化后需重新索引或使用新的 Chroma 集合，系统不会自动删除旧向量。

客户知识库对外提供 `/ai/knowledge/members` 和 `/ai/knowledge/members/{user_id}/access` 管理接口，前者转发员工变更，后者只改本地 ACL；前端入口为“AI 知识库 → 员工与权限”。

桌面端员工不直接使用云面板账号登录客户知识库：桌面端先向云面板请求绑定实例的短期身份凭证，再调用 `/system/auth/cloud-exchange` 建立本地会话；检索使用 `POST /ai/knowledge/search`，由本地会话和 ACL 决定结果范围。客户知识库每次认证请求都会向云面板复核身份，云端员工停用或关闭知识库权限时拒绝后续请求。

## 当前仍待补齐

- 客户服务器的数据库迁移、服务凭证和实例地址配置；
- 桌面端、云面板、客户知识库的真实环境联调和部署包；
- 云面板面向内部管理员的员工管理页面。

首次部署还需通过 `KB_BOOTSTRAP_CLOUD_USER_ID` 指定首个客户侧知识库管理员；该用户同步后成为本地 `kb_owner`，随后可移除该环境变量。以上未完成项不改变当前边界：账号密码事实仍在云面板，本地知识库只保存最小员工映射和 ACL，桌面端不保存 Provider 密钥或云端密码。

# 客户知识库边界与数据库说明

## 定位

本项目是部署在客户服务器上的客户知识库。一套部署对应一个公司，因此本项目不实现 SaaS 多租户，也不在知识库业务表中增加 `tenant_id`。云面板是账号和授权总控台，客户不登录云面板管理界面；客户使用云面板维护的账号登录自己的客户知识库。

## 三个项目的责任

| 项目 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 桌面端 | 用户使用桌面 AI、模型和工具 | 不直接管理客户知识库 ACL |
| 云面板 | 公司、员工账号、密码哈希、员工状态、桌面端/知识库/模型产品权限、客户知识库资源目录和员工知识库授权；提供内部企业用户管理和客户 KB 受限成员 API | 不保存客户知识库文档和向量 |
| 客户知识库 | 文档、分块、向量、知识库、云端授权的本地执行投影、客户侧员工管理界面；通过受限 API 代理账号和授权操作 | 不保存员工密码，不直接访问云面板数据库，不成为云端账号或知识库授权事实源 |

## 账号管理入口

企业用户有两个受控操作入口：

- 我方内部运营人员可以在云面板企业用户管理中创建、查询、修改或停用企业用户；
- 客户可以在客户知识库的“员工与知识库权限”页面发起相同操作，知识库后端使用绑定实例的服务凭证调用云面板成员 API。

两条入口最终都由云面板写入或更新 `sys_user` 和 `cp_membership`。客户知识库只保存 `kb_member` 的最小投影；知识库授权保存时先调用云端 ACL 接口，再把返回的授权集合投影到本地，不能直接操作云面板数据库。删除账号按云端接口合同执行；涉及历史数据时优先采用停用/撤销，不在客户知识库本地硬删云端账号。

客户知识库的“系统管理 → 用户管理”不再作为企业员工入口；企业员工统一使用“AI 知识库 → 员工与知识库权限”，账号事实由云面板维护。

## 客户知识库首次绑定

客户首次打开知识库登录页时，点击“首次使用？绑定云面板”。部署管理员填写：

1. 客户知识库本地超级管理员账号和密码；
2. 云面板登记该知识库实例后生成的实例 ID 和服务凭证；云面板成员服务地址由客户知识库部署配置提供，不在登录页重复填写。

首次绑定时，知识库后端先校验本地超级管理员，再通过绑定实例的受限成员 API 创建同名企业超管；请求使用稳定幂等键，返回结果必须是当前企业的 `role=owner`，否则拒绝保存绑定。更新绑定时，表单中的账号和密码代表目标实例的企业超管；知识库先读取目标实例成员目录确认同名账号属于当前企业且 `role=owner`，再通过云端身份登录验证密码。普通成员、角色缺失、账号不存在或密码错误均拒绝换绑，旧绑定保持不变。远端校验或创建成功后，服务凭证只以加密形式保存在客户知识库的受保护配置表中，不进入浏览器、不回显给员工，也不直接访问云面板数据库。绑定完成后，员工直接使用云面板创建的企业员工账号和密码登录知识库。

`KB_CONTROL_PLANE_API_URL`、`KB_CONTROL_PLANE_INSTANCE_ID` 和 `KB_CONTROL_PLANE_SERVICE_CREDENTIAL` 仍可作为部署自动化或本地开发的服务端 fallback；页面绑定成功后优先使用数据库中的加密配置。

## 数据库表

### `kb_member`

云端员工在客户知识库中的最小映射。`cloud_user_id` 是跨数据库的外部 ID，不建立跨库外键。

保存：

- 云端用户 ID、用户名、姓名、邮箱；
- 云端账号状态；
- 云端返回的知识库产品生效权限；
- 本地角色和最近同步时间。

不保存：

- 员工密码或密码哈希；
- 云面板服务凭证明文；绑定配置表只保存加密后的服务凭证，不进入 `kb_member` 等业务表；
- 云面板完整组织目录。

### `kb_knowledge_base_acl`

云端员工授权在客户知识库中的执行投影：

- `member_id` → `kb_member.id`；
- `knowledge_base_id` → `ai_knowledge_base.id`；
- `granted_by_id` 仅保留兼容字段，不作为授权事实来源；
- 云面板以稳定知识库 `uuid` 管理授权，本地通过 `knowledge_base_id` 映射执行；
- 使用软删除实现投影撤销，唯一约束防止重复授权。

## 权限判定

普通员工访问指定知识库时必须同时满足：

1. 本地存在未删除的 `kb_member` 映射；
2. 云端账号状态为启用；
3. 云端知识库产品权限为启用；
4. 云面板返回当前员工已获授的知识库稳定资源键；
5. 本地知识库未删除且已启用；
6. `kb_knowledge_base_acl` 与云端授权投影一致。

任意条件不满足即拒绝。超级管理员可管理本地知识库；检索请求必须经过知识库 ACL。

## 云端接口

客户知识库通过服务端受保护配置中的实例级服务凭证调用：

- `GET /platform/client/kb-instances/{instance_id}/members`：同步员工映射；
- `POST /platform/client/kb-instances/{instance_id}/members`：创建员工；
- `PATCH /platform/client/kb-instances/{instance_id}/members/{user_id}`：更新员工及产品权限；
- `GET /platform/client/kb-instances/{instance_id}/members/{user_id}/knowledge-bases`：读取云端员工知识库授权；
- `PUT /platform/client/kb-instances/{instance_id}/members/{user_id}/knowledge-bases`：以稳定资源键替换员工知识库授权并同步资源目录；
- `GET /platform/client/kb-instances/{instance_id}/embedding-config`：读取向量来源、模型和地址，不返回 Provider Key。

云面板保存向量模型后，会通过实例服务凭证自动推送非敏感的向量配置到客户知识库；客户知识库不展示“模型配置”页面，仅通过受保护的推送接口应用运行时配置。推送不会传递或保存云面板 Provider Key，远程 embedding 的 API Key 仍由客户服务器环境变量提供；模型变化后需重新索引或使用新的 Chroma 集合，系统不会自动删除旧向量。

客户知识库对外提供 `/ai/knowledge/members` 和 `/ai/knowledge/members/{user_id}/access` 管理接口，前者转发员工创建、查询、修改和停用请求，后者读取或替换云端授权并刷新本地执行投影；前端入口为“AI 知识库 → 员工与知识库权限”。跨项目只传知识库稳定 `uuid`，前端仍可使用本地整数 ID 选择资源。

云面板保存模型请求日志后，会向绑定的客户知识库推送不含提示词、响应正文、凭证或密钥的模型用量事件，并携带可选的云端用户标识和用户名。知识库通过 `POST /ai/chat/model-usage/push` 接收并按云面板请求号幂等落库；客户知识库管理员首页通过 `GET /ai/knowledge/usage-summary` 展示近 7 日请求数、输入 Token、输出 Token、人民币费用以及按员工汇总的 Token/费用。旧事件没有用户标识时归入“未知用户”。推送失败不会阻塞云面板模型请求，客户知识库首页只展示本地已接收的投影数据。

首页另通过 `GET /ai/knowledge/billing-summary` 从云面板读取当前企业的汇总额度。云面板的 `GET /platform/client/kb-instances/{instance_id}/billing` 只返回该服务凭证所属企业的免费额度、付费余额、可用额度和员工数，不返回员工个人余额；客户知识库不拥有额度扣减权，也不接收支付回调。对公转账到账后，由平台管理员在云面板“企业额度”页面手工调整企业付费余额，模型请求完成后由云面板按人民币费用自动结算。

客户员工可以使用云面板维护的账号密码登录客户知识库；知识库后端将登录请求交给云面板核验，再建立本地会话。桌面端员工不把云端密码交给客户知识库，而是先向云面板请求绑定实例的短期身份凭证，再调用 `/system/auth/cloud-exchange` 建立本地会话。检索使用 `POST /ai/knowledge/search`，由本地会话和 ACL 决定结果范围。客户知识库每次认证请求都会向云面板复核身份，云端员工停用或关闭知识库权限时拒绝后续请求。

员工可以在客户知识库右上角头像菜单中选择“修改密码”。请求由知识库服务端转发到云面板，客户知识库不保存员工密码；修改成功后当前会话立即失效，需要使用新密码重新登录。

## 当前仍待补齐

- 客户服务器的数据库迁移和真实首次绑定联调；
- 桌面端、云面板、客户知识库的真实环境联调和部署包。

首次部署仍可通过 `KB_BOOTSTRAP_CLOUD_USER_ID` 指定预先由云面板创建的首个客户侧知识库管理员；绑定成功同步后成为本地 `kb_owner`，随后可移除该环境变量。以上未完成项不改变当前边界：账号密码和员工知识库授权事实仍在云面板，本地知识库只保存最小员工映射、ACL 执行投影和受保护的加密绑定配置，桌面端不保存 Provider 密钥或云端密码。

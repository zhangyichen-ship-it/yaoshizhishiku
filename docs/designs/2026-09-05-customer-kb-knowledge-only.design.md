# 客户知识库仅保留知识库能力

## 目标

客户知识库只提供知识库、文档索引、召回验证和员工知识库授权；云面板继续独立提供 AI 对话与会话记录。

## 主链路

客户知识库菜单种子将 `AI` 目录重定向到 `/ai/knowledge`，移除 `Chat` 与 `Memory` 页面。后端插件不再注册聊天 WebSocket、会话 CRUD 或记忆管理路由，云端员工权限映射也不再授予 `module_ai:chat:*` 和 `module_ai:session:*`。向量配置推送保留为云面板到客户知识库的受保护内部接口，不作为客户菜单入口。

已有数据库通过增量迁移删除聊天和会话菜单及其角色关联；不删除历史会话表或数据，避免把代码裁剪误变成数据清除。

## 非目标

- 不修改云面板的 AI 对话、会话记录菜单、接口或权限。
- 不删除知识库、文档、Chroma、embedding、检索和员工 ACL 能力。
- 不在客户知识库新增另一套静态路由或权限来源。

## 验收

- 客户知识库菜单和 `USER` 种子不再包含 AI 对话、会话记录或对应权限。
- 启用 AI 插件时 `/ai/chat/list`、`/ai/chat/ai-chat`、`/ai/memory/list` 返回 404，知识库路由仍可注册。
- 云面板种子 JSON 和初始化逻辑保持原有 AI 对话/会话记录内容。

## 首页重设计（2026-09-06）

### 用户任务

客户知识库管理员登录后，先判断知识库工作台是否可用，再从首页进入知识库、文档、检索验证或员工权限页面，并在需要时查看账号、系统健康和云面板用量。

### 现状证据与约束

- 当前首页已经由 `userStore` 提供动态菜单、权限和账号信息，并通过现有接口读取健康、模型用量和企业额度。
- 客户知识库只保留知识库、文档、检索和员工知识库授权；首页不新增 AI 对话、会话、记忆或模型配置入口。
- 首页是客户侧单实例控制台，不引入租户切换、第二套路由/权限源或静态伪造统计。

### 方案比较与冻结决策

| 方案 | 判断 | 取舍 |
| --- | --- | --- |
| 继续使用系统总览四卡片 | 不采用 | 实现成本最低，但用户进入后仍要先理解通用后台分类，知识库主任务不突出。 |
| 知识库运营台（推荐） | 采用 | 首屏以工作台状态和实际知识库入口为主，保留现有真实统计作为次级信息；不改变数据 owner，改动可逆且验证直接。 |
| 知识库分析大盘 | 延后 | 需要文档索引、知识库规模等新的聚合接口，当前没有足够数据合同，不能用占位指标填充。 |

### 信息架构与主链路

1. 页面标题改为“知识库工作台”，说明首页用于管理知识资产、检索质量和访问范围。
2. Hero 仅展示当前用户、会话状态和工作台定位；视觉上使用“知识索引/运营台”而非通用欢迎页。
3. 快捷入口从当前动态菜单树的 `AI` 知识库子菜单生成，只渲染实际已下发且非按钮的菜单；点击后沿现有路由进入对应页面。
4. 指标区保留可见菜单、权限点、授权角色和（有权限时）系统健康；用量、额度和登录趋势保留在下方，避免首屏被后台统计占满。
5. 空、加载、错误和无权限状态继续沿用现有数据状态与文案，不因视觉重排隐藏错误；健康检查仍只对超级管理员开放。

### Owner、删除点与非目标

- 菜单、权限、账号的 owner 仍为 `userStore`；健康、用量和额度的 owner 仍为各自现有 API 与首页状态，不新增 manager、service 或接口。
- 删除首页“通用欢迎页”作为主视觉和不可操作的模块行，合并为知识库快捷入口；不删除任何业务路由或权限。
- 不改后端、数据库、云面板 AI/会话能力、知识库/文档/检索/员工权限业务页面及其数据合同。

### 验收

- 桌面端首屏能看见知识库工作台定位、当前状态和动态知识库入口；入口使用实际菜单路径，键盘可聚焦和触发。
- 普通员工只看到已授权的入口和允许展示的统计；超级管理员额外看到健康、登录趋势、用量和额度状态。
- `pnpm type-check` 与 `pnpm build` 通过；在可用运行环境中检查桌面窄屏、加载、空数据、接口错误和深色主题表现。

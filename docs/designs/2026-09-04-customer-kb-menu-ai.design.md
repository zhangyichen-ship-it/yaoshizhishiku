# 客户知识库菜单与 AI 入口

## 用户任务

客户知识库管理员登录后，只看到与知识库运营相关的菜单，并能进入 AI 对话、知识库、文档和员工权限功能。

## 当前事实

- 侧栏菜单由后端 `platform_menu` 种子数据和数据库菜单树共同提供，前端登录后动态注册路由。
- `字典管理` 和 `参数配置` 是 FastapiAdmin 的通用后台工具，不是客户知识库业务入口。
- 字典表和参数表仍被登录、系统参数缓存和数据字典缓存使用，不能随菜单一起删除。
- `module_ai` 是现有 AI、RAG、知识库和员工 ACL 的唯一模块入口。
- AI 依赖已经安装，但开发环境 `AI_ENABLE=False`，因此后端会跳过 AI 路由、模型和 AI 菜单种子。

## 冻结方案

1. 从 `platform_menu.json` 移除 `Dict`、`Params` 两个菜单树。
2. 用 Alembic 迁移清理已有数据库中的两个根菜单、按钮子项及角色关联；不删除业务表和缓存服务。
3. 开发环境打开 `AI_ENABLE`。AI 依赖由 `uv sync --extra ai` 提供，启动时继续使用 `uv run --extra ai`，确保 reload 子进程继承 AI 依赖；向量默认使用本地 fastembed，AI 对话仍需配置可用的 chat endpoint 和模型。
4. 不新增前端静态 AI 菜单，继续使用后端菜单权限投影，避免菜单、权限和路由出现第二套来源。

## 非目标

- 不删除字典/参数后端 API、ORM 模型、数据库表或内部缓存初始化。
- 不替用户填写模型 API 地址、API key 或云面板服务凭证。
- 不改变云面板账号、员工同步和知识库 ACL 规则。

## 验收标准

- 重启后端并刷新登录态，侧栏不再出现“字典管理”“参数配置”。
- AI 依赖齐全且 `AI_ENABLE=True` 时，菜单树包含“AI 知识库”及其授权子菜单，OpenAPI 包含 `/ai` 路由。
- 已有数据库执行迁移后，两个菜单及其角色关联被清理，其他系统菜单、用户和知识库数据不受影响。
- 未配置 chat endpoint 时，AI 入口可以显示，但对话请求应提示模型配置问题；本地 embedding 不因缺少远程 embedding 配置而失效。

# 客户知识库更新云面板凭证

## 目标

客户知识库首次绑定和更新绑定时，都只允许使用云面板中已经存在、属于当前企业且角色为 `owner` 的成员；绑定流程不自动创建云端用户。

## 主链路

客户知识库服务端用新凭证读取当前实例员工目录，按本地管理员用户名查找云端成员。未找到同名成员时直接拒绝绑定，不调用成员创建接口；找到成员后先检查返回的 `role` 必须为 `owner`，再调用受限的 `PATCH /kb-instances/{instance_id}/members/{user_id}`，同步管理员资料和产品开关但不发送本地管理员密码。角色不是 `owner`、角色缺失或成员不在当前企业时均拒绝绑定，不保存新配置。远端操作成功后，才写入客户知识库的加密绑定配置。

## 约束与非目标

- 云面板控制平面接口、租户边界和客户知识库的单组织边界不变。
- 云面板 `cp_membership.role=owner` 是企业超管标识，普通企业成员保持 `member`；普通成员创建和更新接口不能借绑定流程改变角色。
- 客户知识库初始化不自动创建云端用户；需要先由云面板管理员创建企业成员并设置为企业超管，再完成绑定。
- 不在客户知识库新增云端用户 ID 持久化字段，不新增迁移。
- 不通过更新绑定凭证修改云端管理员密码；密码仍由云面板员工账号管理。
- 服务凭证不写入日志或前端响应原文。

## 验收

- 已存在同名且 `role=owner` 的云端成员时，绑定调用 `PATCH`，不会调用 `POST`，并保存新凭证。
- 云端目录没有同名成员时，拒绝绑定，不调用 `POST`，也不保存绑定配置。
- 已存在同名但不是 `owner`、角色缺失或不在当前企业时，拒绝更新，不调用 `PATCH`，也不保存新凭证。
- 远端接口失败时不保存新的本地绑定配置。
